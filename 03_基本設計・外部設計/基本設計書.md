# 基本設計書

## 1. 文書概要

| 項目 | 内容 |
| :--- | :--- |
| 文書名 | AIMD Studio 基本設計書 |
| 対象 | VS Code 拡張機能「AIMD Studio」 |
| 実装言語 | TypeScript |
| 文書目的 | 要求仕様をもとに、実装着手前のたたき台となる基本設計を整理する |
| 参照元 | `02_要件定義/AIMDStudio.md` / `02_要件定義/AIMDプロジェクト仕様.md` |

本書は、AIMD（AI Markdown Project）を扱う VS Code 拡張機能の基本設計たたき台です。  
要求仕様に記載された内容をベースに、画面、機能、構成、データ、非機能要件の観点で設計方針を整理します。  
要件から確定できない項目は、設計内で `[未検討]` と明記します。

## 2. システム概要

### 2.1 目的

- Markdown 文書を章単位で分割管理し、VS Code 上で編集しやすくする
- AIMD 形式のプロジェクトでは、専用ツリーと保護制御により構造化編集を支援する
- 通常 Markdown 編集でも、入力補助・装飾・画像保存などの利便性を提供する
- 生成 AI 連携時に、文書構造とメタデータを利用して安全な変更提案を可能にする

### 2.2 動作モード

| モード | 判定条件 | 主な提供機能 |
| :--- | :--- | :--- |
| AIMD モード | ワークスペースルート名が `.aimd` で終わる | AIMD Explorer、構成バリデーション、目次同期、メタデータ保護、AI 連携 |
| 通常モード | 上記以外 | Markdown 編集補助、画像保存、スラッシュコマンド、スタイル操作、テーブル編集 |

### 2.3 想定利用者

- Markdown を利用して設計書・仕様書を作成するユーザー
- 構造化文書を章・節単位で管理したいユーザー
- GitHub Copilot 等の生成 AI と協調して文書編集を行うユーザー

## 3. システム構成

### 3.1 全体構成

本拡張機能は VS Code Extension Host 上で動作し、以下の要素で構成する。

1. 拡張機能本体
2. サイドバー UI（AIMD Explorer）
3. エディタ連携機能
4. ファイルシステム監視・更新機能
5. AI 連携機能
6. Git / SCM 連携機能

### 3.2 論理コンポーネント

| コンポーネント | 役割 | 主な VS Code API / 技術 |
| :--- | :--- | :--- |
| Extension Activation Controller | 拡張機能起動、モード判定、各機能初期化 | `activate`, `workspace.workspaceFolders` |
| Mode Manager | AIMD / 通常モードの状態管理 | Context / 内部状態管理 |
| AIMD Explorer Provider | AIMD 専用ツリー表示 | `TreeDataProvider`, `TreeView` |
| Editor Assist Controller | スラッシュコマンド、改行補助、スタイル操作、テーブル編集 | `CompletionItemProvider`, `commands`, `CodeLens` など |
| Image Asset Manager | 画像貼り付け、命名、保存先決定、参照更新 | `workspace.fs`, `window.showInputBox` |
| Structure Sync Manager | 目次同期、命名規則検査、Quick Fix 連携 | `FileSystemWatcher`, `DiagnosticCollection`, `CodeActionProvider` |
| Metadata Guard | `.aimd-meta` 保護、表示制御、保存警告 | `FileDecorationProvider`, `TextDocumentContentProvider` |
| AI Harness Coordinator | AI 用コンテキスト生成、差分プレビュー、採用/破棄制御 | Language Model API（利用可能な VS Code 環境が前提）、Webview [未検討] |
| SCM Integration Manager | AI ブランチ生成、差分整理表示、コミット支援 | Git 拡張 API |
| Conversion Wizard | 既存 Markdown / フォルダ構成の AIMD 変換 | `QuickPick`, `InputBox`, ファイル操作 |

## 4. 機能基本設計

### 4.1 起動・モード判定

- 拡張機能有効化時に各 workspace folder 名を取得する
- workspace folder 名の末尾が `.aimd` の場合は、そのフォルダを AIMD モード対象として有効化する
- AIMD モード時は AIMD Explorer、構成監視、メタデータ保護を有効化する
- 通常モード時は Markdown 編集支援のみ有効化する
- AIMD 固有機能は `.aimd` 判定された workspace folder 配下のファイルを開いた場合のみ適用する
- 共通編集支援機能は全ワークスペースで有効化し、AIMD Explorer は `.aimd` 判定された workspace folder ごとに表示する

### 4.2 AIMD Explorer

| 項目 | 設計方針 |
| :--- | :--- |
| 表示対象 | `.aimd-chapter` / `.aimd-section` / `.aimd-subsection` / 末端 `.md` / `99_Image` / `.aimd-meta` |
| 表示順 | 接頭辞の連番順を基本とする |
| アイコン | 階層別に専用アイコンを割り当てる |
| 操作 | 新規作成、削除、ドラッグ＆ドロップ並び替え |
| 保護 | `.aimd-meta` は鍵アイコンとグレーアウト表示 |
| 更新契機 | ファイル操作時と監視イベント受信時に再描画 |

### 4.3 Markdown 編集支援

| 機能 | 基本設計 |
| :--- | :--- |
| スラッシュコマンド | 行頭または空行で `/` 入力時に候補を表示し、選択した Markdown 断片を挿入する |
| スマート改行 | Enter 入力時に GFM ハードブレイク用スペースを自動補完する |
| スタイルコントロール | コマンドまたはパネルから文字装飾を選択し、インライン HTML を挿入する |
| テーブルエディタ | 表編集中のみ操作 UI を表示し、行列追加・削除・貼り付け変換を行う |

- テーブル編集 UI を CodeLens / Webview / インライン Widget のどれで実装するかは `[未検討]`
- スタイルコントロールの UI 形式（サイドパネル / コマンドパレット / ツールバー）は `[未検討]`

### 4.4 画像ハンドリング

| 項目 | AIMD モード | 通常モード |
| :--- | :--- | :--- |
| 入力契機 | 画像ペースト、ドラッグ＆ドロップ | 同左 |
| 名称入力 | InputBox で任意名称を受付 | 同左 |
| 保存先 | 既定は親章配下の `99_Image/`。同一画像を複数章から参照する場合は最も近い共通祖先配下の `99_Image/`、共通祖先がルートのみならルート `99_Image/` | 編集中 Markdown と同階層の `asset/` |
| 命名規則 | `XX_ファイル名_figYY_(入力名称).png` | 同左 |
| 参照更新 | Markdown へ相対パスを挿入、必要に応じて既存参照も更新 | 挿入のみ |

- 画像連番の採番単位（章単位 / ファイル単位 / プロジェクト単位）は `[未検討]`
- ドラッグ＆ドロップ画像とクリップボード画像の共通処理化方針は `[未検討]`

### 4.5 AIMD 構造同期

- ファイル・フォルダ作成時に拡張子と命名規則を補完する
- 並び替え時は接頭辞番号と目次リンクを同期更新する
- 目次ファイルは、前書きファイル `00_初めに.md` が存在しない場合は `00_目次.md`、存在する場合は `01_目次.md` として生成・更新する
- 構成不正を検出した場合は Diagnostics と Quick Fix を提示する
- 手動変更ガードの適用範囲（目次本文すべて / リンク部分のみ）は `[未検討]`

### 4.6 メタデータ保護

- `.aimd-meta/` 配下は通常操作から保護対象とする
- `.aimd-meta/` の正規オープン経路は AIMD Explorer または専用コマンド経由の読み取り専用仮想ドキュメントとする
- ワークスペースエクスプローラー等から実ファイル URI が直接開かれた場合は警告表示後、閲覧用の仮想ドキュメントへ誘導し、実ファイルの直接編集はサポート対象外とする
- AI による更新時のみメタデータ保護サービス（実装例: `metadataGuardService.ts`）経由の内部書き込みを許可し、通常のテキスト編集・保存経路とは分離する
- 手動変更が保存された場合は構成検査で検知し、バックアップからの復旧コマンドを提示する
- 保護範囲は VS Code 上の表示・編集・監視・復旧案内による論理保護とし、OS のファイル権限変更までは行わない

### 4.7 AI 連携

| 項目 | 基本設計 |
| :--- | :--- |
| 入力 | ユーザーが AI ディスカッションパネルから指示を送信 |
| コンテキスト生成 | `AI_RULES.md`、`AI_CONTEXT.md`、`manifest.yaml` を収集してプロンプトへ注入 |
| 出力 | 変更提案を差分として受領し、プレビューで可視化 |
| 反映 | ユーザーが Apply / Discard を選択 |
| メタデータ更新 | 構成変更時はユーザー承認後に直列更新 |

- AI ディスカッションパネルの UI 実装方式（Webview View / Chat Participant 連携）は `[未検討]`
- 差分レンダリングの実装方式（独自 Preview / 既存 Markdown Preview 拡張）は `[未検討]`
- AI 連携基盤は VS Code Language Model API を前提とし、将来の複数バックエンド対応はアダプタ層で吸収する方針とする
- 対象環境は VS Code 上で Language Model API が利用可能で、かつ対応する AI プロバイダ拡張の認証が完了している状態を前提とする

### 4.8 Git / SCM 連携

- AI 適用時に `ai/<yyyyMMddHHmmss>-<targetSlug>-<intentSlug>` 形式のブランチを作成する
- 章・節単位で差分を把握しやすい表示を行う
- コミットメッセージは要約 + 理由/影響範囲の複数行形式で生成する
- `<targetSlug>` と `<intentSlug>` は英小文字・数字・ハイフンのみを許可し、空白や記号は `-` に正規化、連続ハイフンは 1 つに圧縮、先頭末尾ハイフンと `.` は除去する
- 正規化後に空文字となる場合は `target` / `intent` を代替値として使用する
- Git 連携は VS Code の Git 拡張 API を正式な実装経路とし、ブランチ作成・差分取得・コミット下書き生成を同 API 経由で行う
- SCM 自動連携機能は VS Code 標準 Git 拡張がインストール済みかつ有効であることを前提条件とする
- AI 変更提案の差分プレビュー生成は Git 拡張 API がなくても実行可能とする
- Git 拡張 API が利用可能な場合の Apply は、AI ブランチ自動作成後に実行する安全運用を標準とする
- Git 拡張 API が利用できない、またはブランチ作成に失敗した場合は in-place Apply を無効化し、差分はパッチファイルとしてエクスポートしてユーザーの手動確認・適用に委ねる

### 4.9 AIMD 変換ウィザード

- 標準リネームモードでは既存構造を維持しつつ拡張子付与、連番整理、目次生成、メタデータ初期化を行う
- AI 支援変換モードでは文書構造解析結果を提示し、ユーザー承認後に再配置する
- 大量ファイル変換時のロールバック方針は `[未検討]`
- 変換対象外ファイルの扱いは `[未検討]`

## 5. 画面・UI 基本設計

### 5.1 画面一覧

| 画面 / UI | 概要 | 対象モード |
| :--- | :--- | :--- |
| AIMD Explorer | 構造化ツリーを表示する専用サイドバー | AIMD |
| Markdown エディタ補助 | スラッシュコマンド、表編集、スタイル操作 | 共通 |
| 画像名称入力ダイアログ | 画像保存名を入力する | 共通 |
| 警告トースト / Quick Fix | 構成不正を通知し自動修正を案内する | AIMD |
| AI ディスカッションパネル | AI への指示と応答表示 | AIMD |
| Preview Diff 画面 | 変更前後差分の可視化と採用/破棄操作 | AIMD |
| AIMD 変換ウィザード | 変換モード選択と実行確認 | AIMD / 通常 |

### 5.2 UI 設計上のポイント

- 通常モードでは既存の Markdown 編集体験を阻害しない
- AIMD モードでは構造保護を優先し、誤操作を防ぐ導線を設ける
- AI 操作は「提案」と「反映」を明確に分離する

### 6.1 管理対象ファイル

| ValidationIssue | `severity`, `message`, `targetPath`, `fixType` | 構成診断 |

## 7. 非機能基本設計

| 観点 | 基本設計 |
| :--- | :--- |
| 性能 | ファイル監視や目次再生成はデバウンスし、編集中の入力遅延を抑える |
| 信頼性 | メタデータ更新時はバックアップを保持し、失敗時に復元できるようにする |
| 保守性 | 機能単位で TypeScript モジュールを分割し、モード依存を疎結合に保つ |
| 拡張性 | AIMD 固有機能と共通 Markdown 補助機能を分離し、将来機能を追加しやすくする |
| 可搬性 | Markdown 本文は GFM/標準 VS Code でも扱える記述を維持する |
| セキュリティ | `.aimd-meta` や AI に渡すコンテキストは意図しない改変・過剰公開を防ぐ |

- 対応 OS のサポート範囲は `[未検討]`
- オフライン利用時の AI 機能劣化方針は `[未検討]`
