# AIMDプロジェクト仕様

本書は、構造化ドキュメント規格である「AIMD（AI Markdown Project）」の設計仕様です。

---

# パート1: AIMD プロジェクト構成仕様書（仕様書Md記法方針）

## 1. 概要と基本理念
AIMD（AI Markdown Project）は、人間・Git・生成AIが文書構造をシームレスに解釈・共有・編集するために策定されたディレクトリ規格です。

* **フォルダによる階層表現**: 単一の巨大なファイルによるコンフリクトやAIの認識精度低下を防ぐため、章・節・項をコンテナフォルダとして分割します。
* **本文内章立ての許容**: フォルダ階層による分割だけでなく、各 `.md` ファイル内で見出し構文（`#`, `##` 等）を用いて章立てを行うことも可能です。
* **機械可読メタデータの分離**: AI向けコンテキストや構成メタデータは専用の隠しフォルダで集中管理します。

---

## 2. フォルダ・ファイル規格一覧

| 区分 | 命名規則 / 拡張子 | 役割・説明 |
| :--- | :--- | :--- |
| **ルートフォルダ** | `<文書名>.aimd/` | 文書全体を内包する最上位コンテナ。 |
| **大項目（章）** | `XX_<名前>.aimd-chapter/` | 第1階層の章コンテナ（WordのHeading 1相当）。 |
| **中項目（節）** | `XX_<名前>.aimd-section/` | 第2階層の節コンテナ（WordのHeading 2相当）。 |
| **小項目（項）** | `XX_<名前>.aimd-subsection/` | **第3階層以降の全下位階層**に統一して使用するコンテナ。 |
| **本文ファイル** | `XX_<名前>.md` | 実際のドキュメント本文。内部での見出し記述も可能。 |
| **画像フォルダ** | `99_Image/` | 画像専用フォルダ。必ず接頭番号「99」を付与。 |
| **メタデータフォルダ** | `.aimd-meta/` | AI用設定・構成メタデータを格納する隠しフォルダ。 |

※ 既存資産の取り込み時は接頭番号の区切り文字として `-` と `_` のどちらも解釈可能としますが、新規作成・保存・本書内の説明と例示はすべて `_` を正式表記として扱います。

---

## 3. 目次（目次.md）とナンバリング規則

* **章配下の目次廃止**: 各章（`.aimd-chapter`）や節の配下には、個別の `目次.md` は配置しません。
* **ルート配置と前書き対応**: ルート直下に全体目次を配置します。任意で目次の前に「初めに」（前書き）を挟むことができ、その有無によってナンバリングが変化します。
* **目次の必須要件**:
  1. 必ずすべての末端 `.md` ファイルを掲載すること。
  2. 目次から各ページへ遷移できるリンクを設定すること。
  3. 階層構造を持たせ、親子関係が明示される形式で記載すること。

### ナンバリングの分岐パターン
| パターン | ナンバリング例 | 説明 |
| :--- | :--- | :--- |
| **A: 前書きなし** | `00_目次.md`<br>`01_概要.aimd-chapter` | 目次が `00` となり、直後から章が連番で始まります。 |
| **B: 前書きあり** | `00_初めに.md`<br>`01_目次.md`<br>`02_概要.aimd-chapter` | 前書きが `00`、目次が `01` となり、章は `02` から始まります。 |

---

## 4. 末端 md ファイルの記述規則

* **連番付与**: すべての末端 `.md` ファイルには必ず連番を付与します。
* **命名形式**: ファイル名は必ず `XX_<ファイル名>.md` の形式にします。
* **ページナビゲーション**: すべての末端 `.md` ファイルは、ヘッダーおよびフッターの両方に `前ページ`、`目次`、`次ページ` の3要素を持たせます。先頭ページで前ページが存在しない場合、および末尾ページで次ページが存在しない場合は、該当ラベルのリンク先を、その構成で採用している実際の目次ファイル（例: `00_目次.md` または `01_目次.md`）に設定します。
* **見出し記法**:
  * ページ先頭の見出しは必ず `#` で開始します。
  * 小章がある場合は必ず `##` で開始します。
  * その配下にさらに小章がある場合は必ず `###` で開始します。
  * 見出しのタイトルは、必要に応じて内容順に連番を付与して管理します。

---

## 5. 画像管理ルール（99_Image）

| 配置パターン | 格納場所 | 参照パス例（本文からの相対） |
| :--- | :--- | :--- |
| **章内固有の画像** | ファイルが属する親の章直下（`...aimd-chapter/99_Image/`） | `![](./99_Image/diagram.png)` |
| **章を跨ぐ共通画像** | 共通の親階層またはルート直下の `99_Image/` | `![](../99_Image/common_architecture.png)` |

※ 本文 `.md` 内部で見出しを使って小項目を分けている場合でも、添付画像はすべて親の章（`.aimd-chapter`）配下の `99_Image/` に集約されます。

---

## 6. システム管理ファイル（.aimd-meta/）

ユーザーの誤操作を防ぐため、以下のファイルはすべてルート直下の隠しフォルダ `.aimd-meta/` 内に配置し、AIが自動生成・更新します。すべてのファイルは先頭にバージョン管理用ヘッダーを持ちます。

| ファイル名 | 生成・管理主体 | 役割・内容 |
| :--- | :--- | :--- |
| **`manifest.yaml`** | AI（全体で1つ） | プロジェクト全体のディレクトリ構成を把握するための機械可読メタデータ。 |
| **`AI_CONTEXT.md`** | AI | `manifest.yaml` に収まらない背景、目的、全体文脈をまとめた概要書。 |
| **`AI_RULES.md`** | AI | 文書作成・改修時にAIが遵守すべき制約事項・ルール集。 |

## 7. ディレクトリ構造の全体図

```text
Document.aimd/
│
├── .aimd-meta/                         <-- 【隠しフォルダ】ユーザー操作非推奨
│   ├── manifest.yaml                   <-- プロジェクト全体で1ファイルのみ（AI自動生成）
│   ├── AI_CONTEXT.md                   <-- プロジェクト文脈（AI自動生成）
│   └── AI_RULES.md                     <-- 変更厳守ルール（AI自動生成）
│
├── 99_Image/                           <-- 【全体共通画像】章を跨いで利用される画像
│   └── common_architecture.png
│
├── 00_初めに.md                        <-- 【任意】目次の前に入る前書き
├── 01_目次.md                          <-- 【全体目次】全末端 md へのジャンプリンクを持つ
│
├── 02_概要.aimd-chapter/               <-- 【第1階層：大項目】配下に目次は持たない
│   ├── 99_Image/                       <-- 章内固有の画像フォルダ
│   │   └── intro.png
│   ├── 01_目的.md
│   └── 02_背景.md
│
├── 03_システム.aimd-chapter/
│   ├── 99_Image/
│   │
│   ├── 01_ハードウェア.aimd-section/   <-- 【第2階層：中項目】
│   │   ├── 01_CPU.aimd-subsection/     <-- 【第3階層：小項目】
│   │   │   ├── 01_詳細.md
│   │   │   └── 02_仕様.aimd-subsection/ <-- 【第4階層以降】すべて subsection で統一
│   │   │       └── 01_スペック.md
│   │   └── 02_Memory.md
│   │
│   └── 02_ソフトウェア.aimd-section/
│       └── 01_アーキテクチャ.md
│
└── 04_テスト.aimd-chapter/
    └── 01_テスト方針.md
```
